# Support

## Where to get help

| Need | Where |
|---|---|
| Questions, usage help, design discussion | GitHub Discussions on the relevant repository (or the org Discussions) |
| Bug in the compiler, stdlib, registry, or website | Open an issue using the bug report template |
| Feature idea for language or stdlib | See `GOVERNANCE.md`; language and stdlib changes go through RFCs |
| Package registry problems (publish, install, yank) | `registry@xiom-lang.org` or the `registry` repository issues |
| Security vulnerability | `security@xiom-lang.org` (never a public issue) |
| Code of conduct concern | `conduct@xiom-lang.org` |

## Before opening an issue

1. Search existing issues and discussions.
2. Reproduce on the latest release; note `xiom --version` and your OS.
3. Reduce compiler problems to a minimal `.xi` program. A five-line
   reproduction gets fixed; a 500-line project report usually cannot be
   triaged.

## Documentation

- Language guide and reference: `https://docs.xiom-lang.org` (opening with
  the public beta).
- Playground: `https://playground.xiom-lang.org`.
- Repository docs: each repository's `README.md` and `docs/` directory.

## What to expect

XIOM is maintained by a small team. Support is best-effort and community
driven; there is no commercial SLA. Issues that include a minimal
reproduction, expected vs actual behavior, and version information get
triaged fastest.
